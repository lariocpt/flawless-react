# Deep review — September 2026

A whole-product review pass over the B-16-complete tool, tool base `aa03ae7`:
three subsystem reviewers at high effort (analysis/emitter,
runner/CLI/reporting, cross-cutting contracts) over 30k LOC, every candidate
finding then verified by an adversarial pass that tried to refute it. The
same nine — eight findings plus one design tension — survived two independent
verification passes; the three highest-impact were spot-checked in code
before being written down. The round's ethic is the project's own: a fix
without a failing-first test is not shippable. Canonical machine-readable
ledger: [`2026-09-findings.json`](2026-09-findings.json). Deferred
follow-ups: [`backlog.md`](backlog.md), B-27 and B-28.

## What was fixed during the engagement

Eight findings, closed on one branch, each with a test that reddens when the
fix is reverted (mutation probe, 8/8):

- **FR-053 (P0)** the emitted fetch spec's trigger threw for every `getAllBy*`
  selector shape — the non-throwing rewrite only converted the `getByTestId`
  form, so an aria-label/role/text launcher, absent at mount, defeated the
  `if (trigger)` guard and failed all four fetch scenarios on a correct
  component. The rewrite is now anchored per shape
  (`getAllBy* → queryAllBy*`). Proven by execution, not reasoning: the
  emitted spec run under real vitest against a `.map()`-rendered launcher —
  four red with the old line, four green with the fix.
- **FR-056 (P0)** `--changed` exited 0 green saying "nothing affected" for a
  change confined to an unexported component — the file changed, is covered
  through a parent's spec, and the blanket empty-set early return skipped it.
  The early return is gone; vitest `related` now walks the module graph from
  the changed file, and the empty-plan reason distinguishes "nothing
  affected" from "affected, but the selected task(s) narrow by spec name and
  cannot reach them".
- **FR-055 (P1)** same-named components collapsed each other's inline
  summaries: `a/Header.tsx` and `b/Header.tsx` shared one map entry, the
  second file never got its `.flawless.json` sidecar, and every finding
  routed to it was silently dropped — the exact sibling drop `registry.ts`
  dedupes on the full key to prevent. The key is now
  `filePath::componentName`; a child rendered by two parents still collapses
  to one, which is intended.
- **FR-054 (P1)** React Native's `editable` → `disabled` polarity was
  inverted at the `analyse()` surface — a working field read "conditionally
  disabled", a locked one read fillable. Dead in emitted output today (no
  native consumer reads `hints.disabled`), a lie waiting for a custom
  reporter, and the exact field `postDispatch` names as the DOM/native drift
  hazard. A non-editable field is now disabled "always"; an editable one is
  not disabled at all.
- **FR-057 (P1)** `useRef` was modelled as its init argument: `useRef(null)`
  became `null` in the render env, so `ref ? A : B` took the branch the
  component never takes. The binding now resolves to the ref object — an
  opaque truthy `{}` whose `current` is `unknown` (never the init arg: it can
  be reassigned before the JSX runs). Deliberate under-modelling in the safe
  direction; v2 assignment tracing is B-28.
- **FR-058 (P1)** a path parameter before an inline query
  (`/things/${id}?tab=${tab}`) shipped a load target with a dangling
  `?tab=` — a URL the app never requests. The template is now cut at the
  first `?` on every path through `pathOnly`: a query's values come from
  runtime state the pipe cannot carry.
- **FR-060 (P1)** a `"use server"` directive behind a header longer than
  4096 bytes was missed and the module misclassified, which then failed to
  stub the server action in the browser bundle. The bound is 64KB — the read
  runs once per *imported* module, so the bound is a perf choice — and the
  docblock now names the remaining miss of the bound instead of hiding it.
  The principled fix (scan to the first token) is B-27.
- **FR-059 (P2)** vitest's value-taking `--project` was misread as a path
  filter, so `vitest --project unit` counted the project name as a scope and
  a colliding script escaped the "you narrowed the run" warning. `--project`
  joins the value-taking set: it chooses which project runs, not which
  tests.

## Recorded, not changed

**perf-static's per-root count** survived as the round's one design tension.
A shared leaf is counted once per root that reaches it, so a component
imported by many pages multiplies its findings. That is documented intended
behaviour: the finding belongs to every page that ships it, and deduping to
one would hide the multiplicity the triage reader is paying for. Left as-is,
recorded so a future reviewer does not re-derive it as a defect.

**Two deferred follow-ups** are opportunities, not defects: **B-27** (scan
the prologue directive to the first token instead of a byte bound — the cost
is bounded by the per-imported-module read) and **B-28** (useRef v2: trace
`ref.current = X` assignments before the JSX so the read evaluates to `X`;
today's `unknown` is the safe direction, so this buys coverage, not
correctness).

## Dogfood addendum — FR-061

Running the regenerated suite's full plane against the dogfood app surfaced a
ninth finding the review pass itself had not reached: **FR-061 (P0)**. The
browser-spec emitter re-derived host eligibility with its own predicate
(`renderMode === "client"`) instead of asking `hostEligibility` — the single
source the host registry, the report and the unit emitter already consult.
The disagreement showed in both directions: it emitted browser specs for four
client components the host refuses (undecidable render), each red on every
run with "unknown component", and it emitted none for twenty wrappable
compound parts the host does carry. It predates the round (the same four fail
identically at the merge base); the dogfood's full-plane run is what made it
visible, because the last several two-task regenerations never ran the browser
plane. The fix makes the emitter ask `hostEligibility` — the emitted
browser-spec set becomes exactly the host's membership — and stamps browser
specs with a post-write sweep that retires any whose component later leaves
the host (removing untouched tool output, keeping and reporting anything a
human may have worked in). See the ledger entry for the claim, the red-then-
green predicate and sweep tests, and the dogfood verification.
