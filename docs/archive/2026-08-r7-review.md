## The findings that mattered

Four of the six confirmed findings were the same failure class the project
exists to prevent: **a green result nobody earned.**

- An unknown task id was filtered away, so `runCore({taskIds:["unit"]})`
  exited 0 with an empty results array — a run that tested nothing and said
  it was fine.
- `--changed` with a ref git could not resolve reported "nothing affected"
  and exited 0; every `git diff` failed and was skipped with a bare
  `continue`. A typo, or a shallow CI clone, produced a green comparison
  that never happened.
- A file biome could not **parse** was reported clean, because `parse`
  diagnostics were dropped by the a11y sweep's category filter. `a11y: 0
  findings` covered a file the tool never read.
- The emitted RSC spec's only rendered-output assertion could not fail:
  `document.body.innerHTML.length > 0` holds no matter what the component
  produced, because Testing Library always appends its container.

The fifth was a crash *after* all work completed (`--nextjs` with no entry
positional), and the sixth was documentation that B-8/B-9 had already
falsified — including `provider.tsx` described as "written once and never
overwritten" while the code comment three files away says `--force`
regenerates it.

**Method note, stated because it changes how much these numbers are worth:**
nine finder agents produced 45 raw findings (43 after dedup), but the
verification fan-out died mid-run on an account spend limit. Every finding
recorded above was therefore verified by hand with a concrete probe before
being written down, and four claims that could not be reproduced are
recorded in the ledger as *unverified reports*, not as defects. An
unverified finding is not a finding.

## Dogfood round 7 — what B-9 actually bought

Round 6 ended with a corrected diagnosis: of the 42 "return shapes could not
be inferred" markers on mybodycorpai, exactly **one** was the shared-typed
dep the wall was named after; the rest were an unannotated `getDb` (×21),
dotted local calls, and a `cache()`-wrapped export. B-9 was built for that
one dep, and it landed:

| Measure | Round 6 | Round 7 |
| --- | ---: | ---: |
| `TODO(flawless)` markers | 118 | **117** |
| Unit tests generated **and passing** | 508 | **517** |
| Profile tests | 254 | 256 |
| perf-static findings | 245 | **241** |
| Browser / e2e / load | 191 / 39 / 33 | 191 / 39 / 33 |

The marker count moved by one, and that is the honest headline. The *useful*
movement is underneath it: `listMeetingParticipants` now carries a complete
fixture with all three `z.infer` enum members resolved, and enum-typed
**props** produce variant matrices that did not exist before — `RsvpButtons`
gained a four-row `RsvpStatus` matrix, `JobControls` likewise. Nine new
tests, executed green on the first run, against components whose specs
previously passed `undefined` and asserted nothing about those states.

The remaining wall is now fully attributed and none of it is a mystery:
`getDb` (unannotatable by construction), dotted callees (FR-014, deliberately
deferred), and `cache()`-wrapped exports (backlog B-10).

## Gaps and opportunities

Every item below cites something observed this round. Nothing is invented.

1. **The e2e suite is green before it is real** (backlog B-12). The generated
   `global-setup.ts` is a hand-fill stub, and until a human fills it the
   route specs assert `status < 500` against a login redirect — which
   answers 200. The `flawless-e2e-load` skill's anti-vacuous probes exist
   *because* of this. The tool should emit a setup that fails until filled,
   or mark the run as not-yet-meaningful in REPORT.md.
2. **`--ci` suppresses the diagnostics an agent most needs** (B-13).
   `warn()` writes to stderr but is gated on the same flag as `log()`, so
   the mode designed for machines is the mode that loses "your `--api` flag
   was ignored" and "skipping unparseable file".
3. **`--run-tests` with only non-runnable tasks does nothing, quietly**
   (B-14). No message, no marker in the blob.
4. **Repeated work the caches should absorb** (B-15): `parseFile` re-runs
   component detection per call, and `findExportedDecl` re-walks the same
   barrels per member per component. Measured impact is small today (the
   B-7 timing pin still holds), which is exactly why it is an opportunity
   and not a finding.
5. **Distribution remains the only 1.0 gate.** Unchanged since August, and
   deliberately so — it is gated on the owner's go, not on readiness.

### Where that leaves the honest verdict

The August face-off scored flawless 5/5/5/5/5 on determinism, code
ownership, offline operation, marginal cost and category breadth, and **1/5
on maturity/support/community**. Nothing this round changes either half.
What changed is the *quality of the evidence*: the inference frontier that
looked like one wall in round 5 is now measured per callee, the tool caught
four of its own silent-pass paths under adversarial review, and its emitted
artefacts are verified by executing them — including a scoping bug in this
round's own RSC fix, caught because the execution tests exist.

The competitive position is unchanged and worth stating plainly: this is a
single-author 0.3.0-dev tool on a private registry with no support channel,
competing on properties funded vendors cannot retrofit (no LLM anywhere, no
network in the analysis loop, code you own outright, $0 marginal cost) and
losing on the two properties money buys (maturity, framework future-proofing).
Checksum's newly-public $50/mo floor sharpens the trade rather than changing
it: $50/mo buys maintained e2e in your repo with a SaaS in the loop; flawless
buys six test layers, offline, for nothing, with a human filling the fixtures.

**Readiness: 57/70 (81%)**, up one from round 6 — dimension 3 (analysis
soundness) moves to 5 on B-8 + B-9 + the measured dogfood delta; dimension 4
(honesty of findings) holds at 5 because the four silent-pass paths were
found *and* fixed within the round. Verdict unchanged: **A− as an internal
power tool; distribution is the only 1.0 gate.**
