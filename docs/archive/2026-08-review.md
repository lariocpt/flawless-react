# Deep review — August 2026

Four finder passes (analyse/emitter, performance measurement, DX/docs honesty,
test-suite gaps) over tool base `7708cf2`, cross-checked by four dogfood
iterations against mybodycorpai (`apps/web`, 99 files, 183 components).
Canonical machine-readable ledger: [`2026-08-findings.json`](2026-08-findings.json).
Opportunities: [`backlog.md`](backlog.md).

## What was fixed during the engagement

Ten findings closed, each with a failing test first where code changed:

- **FR-001 (P0)** `--run-tests`/`--changed` suite failures never reached the
  exit code — a CI consumer shipped green on red. Both runners' outcomes now
  fold into `exitCode`.
- **FR-002** `bun src/cli.ts` was a silent exit-0 no-op (main was exported,
  never called). This is the mystery the project memory had filed as a sandbox
  problem; the sandbox was innocent.
- **FR-006** style adoption skipped `.mts`, so the one emitted file with that
  extension broke the adopter's `biome ci`. Found by dogfood iteration 1, where
  a no-force regen changed exactly two files and one diff was indentation-only.
- **FR-007** effect-only (`return null`) and base-ui `useRender` components are
  now detected — the two dogfood "no component could be read" files, one of
  which is the shape shadcn's base-ui port emits registry-wide.
- **FR-008** sweeps no longer report the project's own suppressions as
  `suppressions/unused` findings (answering the a11y task's finding had created
  a brand-new react-rules finding).
- **FR-003/005** the README ownership overclaim, the "any re-run is refused"
  claim, the stale `tests/` profile path, and the pre-rework click-rerender
  description now match the code.
- **FR-004** bad `--nextjs` input throws `UsageError` (exit 2), as documented.
- **FR-009** pointing the tool at a directory now names the mistake and the fix.
- **FR-010** the "half a second" claim was measured true (99 files → 463 ms
  median) and now carries the dated measurement.

## The strongest open findings

- **FR-016 (design)** `host/main.tsx` is write-once but contains the mount
  registry: a newly detected component's browser spec can never mount and no
  invocation can fix it — observed live when Badge appeared.
- **FR-017 (design)** `--changed` with the full task selection silently skips
  the affected-test run on an adopted suite (perf-harness's refusal sets
  `anyFailed`). The flag's primary use case needs a task subset to work.
- **FR-011/012/013/014** analyse/emitter correctness: wrapper-typed props
  silently lost; backtick/`${` labels break emitted browser specs; the colocate
  include glob assumes `src/`; dotted data-dep callees produce mocks that crash
  correct RSCs.
- **FR-015** `mock/routes.ts` promises edit-safety its writer does not honour —
  the one write-once claim in the emitted prose that is false.
- **FR-018/022** the repo's own honest-execution pattern stops short of running
  an emitted unit spec under real vitest or any playwright spec under a real
  browser.

## Performance verdict (measured, not felt)

Full 7-task generation over the 99-file corpus: **~0.95 s** user-felt
(median run 825 ms + 110 ms module import + 7 ms bun boot). Analysis alone:
463 ms — the documented claim, confirmed. Process census: exactly 3 child
processes per full run. The sequential analyse loop is **not** worth
parallelising (~2.5% projected); the one real inefficiency is per-entry parse
caches (FR-032, ~13-19% of wall, S effort).

## Dogfood round 4 in one paragraph

Iteration 1 (no-force regen) proved upgrade-in-place is surgical — one file of
real diff — but partial: the harness refuses and the run exits 1 (FR-028).
Iteration 2 ran the full e2e (39/39) and load (33/33 pipes vs committed
baselines, authed, prod build) estate with zero adjustments. Iteration 3
burned findings to zero (a11y 1→0, react-rules 10→0, unreadable files 2→0,
+2 components) through the intended extension points, feeding three tool fixes
back upstream. Iteration 4 exercised `--changed` and `--force`: the write-once
promise held completely, and the clobber surface was exactly the hand-hardened
colocated specs — the datum behind backlog item B-4.

Out-of-the-box coverage of the generated suite on this app, unit layer alone
(v8, vitest): **64.7% of component-file lines** (66.2% lines / 88.9% branches
in `src/components/`), before the browser, profile, e2e and load layers.
